# 数据上下文提取器

一个元技能，从分析师那里提取公司特定的数据知识，并生成定制的数据分析技能。

## 工作原理

此技能有两种模式：

1. **引导模式**：从头创建新的数据分析技能
2. **迭代模式**：通过添加特定领域的参考文件来改进现有技能

---

## 引导模式

使用场景：用户想要为其仓库创建新的数据上下文技能。

### 第一阶段：数据库连接与发现

**步骤 1：识别数据库类型**

询问："您使用的是什么数据仓库？"

常见选项：
- **BigQuery**
- **Snowflake**
- **PostgreSQL/Redshift**
- **Databricks**

使用 `~~数据仓库` 工具（查询和模式）进行连接。如果不清楚，检查当前会话中可用的 MCP 工具。

**步骤 2：探索模式**

使用 `~~数据仓库` 模式工具：
1. 列出可用的数据集/模式
2. 识别最重要的表（询问用户："分析师最常查询的 3-5 个表是哪些？"）
3. 获取这些关键表的模式详情

按方言的示例探索查询：
```sql
-- BigQuery：列出数据集
SELECT schema_name FROM INFORMATION_SCHEMA.SCHEMATA

-- BigQuery：列出数据集中的表
SELECT table_name FROM `project.dataset.INFORMATION_SCHEMA.TABLES`

-- Snowflake：列出模式
SHOW SCHEMAS IN DATABASE my_database

-- Snowflake：列出表
SHOW TABLES IN SCHEMA my_schema
```

### 第二阶段：核心问题（提问这些）

模式发现后，以对话方式提问这些问题（不是一次全部）：

**实体消歧（关键）**
> "当这里的人说 '用户' 或 '客户' 时，他们确切指的是什么？有不同类型吗？"

注意：
- 多种实体类型（用户 vs 账户 vs 组织）
- 它们之间的关系（1:1、1:多、多:多）
- 哪些 ID 字段将它们链接在一起

**主要标识符**
> "[客户/用户/账户] 的主要标识符是什么？同一实体有多个 ID 吗？"

注意：
- 主键 vs 业务键
- UUID vs 整数 ID
- 遗留 ID 系统

**关键指标**
> "人们最常问的 2-3 个指标是什么？每个是如何计算的？"

注意：
- 精确公式（ARR = 月收入 × 12）
- 哪些表/列输入每个指标
- 时间段惯例（过去 7 天、日历月等）

**数据卫生**
> "查询中应该总是过滤掉什么？（测试数据、欺诈、内部用户等）"

注意：
- 始终包含的标准 WHERE 子句
- 指示排除的标志列（is_test、is_internal、is_fraud）
- 要排除的特定值（status = 'deleted'）

**常见陷阱**
> "新分析师通常在处理这些数据时会犯什么错误？"

注意：
- 容易混淆的列名
- 时区问题
- NULL 处理怪癖
- 历史 vs 当前状态表

### 第三阶段：生成技能

创建此结构的技能：

```
[company]-data-analyst/
├── SKILL.md
└── references/
    ├── entities.md          # 实体定义和关系
    ├── metrics.md           # KPI 计算
    ├── tables/              # 每个领域一个文件
    │   ├── [domain1].md
    │   └── [domain2].md
    └── dashboards.json      # 可选：现有仪表板目录
```

**SKILL.md 模板**：参见 `references/skill-template.md`

**SQL 方言部分**：参见 `references/sql-dialects.md` 并包含适当的方言说明。

**参考文件模板**：参见 `references/domain-template.md`

### 第四阶段：打包和交付

1. 在技能目录中创建所有文件
2. 打包为 zip 文件
3. 向用户展示已捕获内容的摘要

## 迭代模式

使用场景：用户有现有技能但需要添加更多上下文。

### 步骤 1：加载现有技能

请用户上传其现有技能（zip 或文件夹），或如果已在会话中则定位它。

阅读当前的 SKILL.md 和参考文件以了解已记录的内容。

### 步骤 2：识别差距

询问："哪个领域或主题需要更多上下文？哪些查询失败或产生错误结果？"

常见差距：
- 新数据领域（营销、财务、产品等）
- 缺失的指标定义
- 未记录的表关系
- 新术语

### 步骤 3：针对性发现

对于识别的领域：

1. **探索相关表**：使用 `~~数据仓库` 模式工具查找该领域的表
2. **提出领域特定问题**：
   - "[领域] 分析使用哪些表？"
   - "[领域] 的关键指标是什么？"
   - "[领域] 数据有什么特殊筛选或陷阱吗？"

3. **生成新参考文件**：使用领域模板创建 `references/[domain].md`

### 步骤 4：更新并重新打包

1. 添加新参考文件
2. 更新 SKILL.md 的"知识库导航"部分以包含新领域
3. 重新打包技能
4. 向用户展示更新后的技能

## 参考文件标准

每个参考文件应包含：

### 表文档
- **位置**：完整表路径
- **描述**：此表包含什么，何时使用
- **主键**：如何唯一标识行
- **更新频率**：数据刷新频率
- **关键列**：包含列名、类型、描述、说明的表
- **关系**：此表如何与其他表关联
- **示例查询**：2-3 个常见查询模式

### 指标文档
- **指标名称**：人类可读名称
- **定义**：简明英文解释
- **公式**：带列引用的精确计算
- **来源表**：数据来自哪里
- **注意事项**：边缘情况、排除项、陷阱

### 实体文档
- **实体名称**：叫什么
- **定义**：在业务中代表什么
- **主要表**：在哪里找到此实体
- **ID 字段**：如何识别它
- **关系**：如何与其他实体相关
- **常见筛选**：标准排除项（内部、测试等）

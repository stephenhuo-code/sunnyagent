# /analyze - 回答数据问题


回答数据问题，从快速查询到完整分析再到正式报告。

## 用法

```
/analyze <自然语言问题>
```

## workflow

### 1. 理解问题

解析用户的问题并确定：

- **复杂度级别**：
  - **快速回答**：单一指标、简单过滤、事实查询（例如："上周有多少用户注册？"）
  - **完整分析**：多维度探索、趋势分析、对比（例如："是什么导致了转化率下降？"）
  - **正式报告**：包含方法论、注意事项和建议的综合调查（例如："准备一份订阅指标的季度业务回顾"）
- **数据需求**：需要哪些表、指标、维度和时间范围
- **输出格式**：数字、表格、图表、叙述或组合

### 2. 获取数据

**优先级 1：如果上下文中已有可用文件（CSV/Excel）：**

 1. 直接使用 `read_file` 工具读取上下文中列出的文件
 2. 解析文件内容，理解数据结构
 3. 继续进行分析

**先级 2：如果已连接数据仓库 MCP 服务器：**

1. 探索 schema 以找到相关的表和列
2. 编写 SQL 查询以提取所需数据
3. 执行查询并获取结果
4. 如果查询失败，调试并重试（检查列名、表引用、特定方言的语法）
5. 如果结果看起来异常，在继续之前进行完整性检查

**优先级 3：如果未连接数据仓库：**

1. 请用户以以下方式之一提供数据：
   - 直接粘贴查询结果
   - 上传 CSV 或 Excel 文件
   - 描述 schema 以便为他们编写查询
2. 如果为手动执行编写查询，使用 `sql-queries` 技能获取特定方言的最佳实践
3. 获得数据后，继续分析

### 3. 分析

- 计算相关指标、聚合和对比
- 识别模式、趋势、异常值和异常
- 跨维度比较（时间段、细分、类别）
- 对于复杂分析，将问题分解为子问题并逐一解决

### 4. 展示前验证

在分享结果之前，进行验证检查：

- **行数完整性**：记录数量是否合理？
- **空值检查**：是否有可能影响结果的意外空值？
- **量级检查**：数字是否在合理范围内？
- **趋势连续性**：时间序列是否有意外的断档？
- **聚合逻辑**：小计是否正确汇总为总计？

如果任何检查引发担忧，进行调查并记录注意事项。

### 5. 展示发现

**对于快速回答：**
- 直接陈述答案并附上相关上下文
- 包含使用的查询（折叠或在代码块中）以便复现

**对于完整分析：**
- 以关键发现或洞察开头
- 用数据表和/或可视化支持
- 注明方法论和任何注意事项
- 建议后续问题

**对于正式报告：**
- 包含关键要点的执行摘要
- 解释方法和数据来源的方法论部分
- 带有支持证据的详细发现
- 注意事项、限制和数据质量说明
- 建议和下一步行动

### 6. 在有帮助时进行可视化

当图表能比表格更有效地传达结果时：

- 使用 `data-visualization` 技能选择正确的图表类型
- 生成 Python 可视化或构建到 HTML 仪表板中
- 遵循可视化最佳实践以确保清晰和准确
- 有图表生成的同时，需要把上一步正式报告同时输出

## 示例

**快速回答：**
```
/analyze 12月有多少新用户注册？
```

**完整分析：**
```
/analyze 过去3个月支持工单数量增加的原因是什么？按类别和优先级分解。
```

**正式报告：**
```
/analyze 准备一份客户表的数据质量评估——完整性、一致性以及需要解决的任何问题。
```

## 提示

- 尽可能具体说明时间范围、细分或指标
- 如果你知道表名，提及它们可以加快流程
- 对于复杂问题，可能会将其分解为多个查询
- 结果在展示前始终会经过验证——如果有异常，LLM标记出来

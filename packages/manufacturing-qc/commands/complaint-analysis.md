分析客户投诉，追溯原因并提出系统化的改善措施。

## 用法

```
/complaint-analysis <自然语言问题>
```

## workflow


### 1. 理解问题
capabilities: text_only
skills: none

**步骤目标**: 解析用户问题，确定分析方向

**输入**: 用户的自然语言问题
**输出**: 问题分类结果（文本）

**注意**: 此步骤只做分析和分类，不要读取数据文件或执行代码。

解析用户的问题并确定：

- **用户意图**：
  - **事实查询**：单一指标、简单过滤、事实查询（例如："小米2025年客诉多少？"）
  - **趋势分析**：多维度探索、趋势分析、对比（例如："是什么导致了客诉上升？"）
  - **问题根因分析**：分析导致问题的原因，那个环节导致了相关问题（例如："什么原因导致了镜头模糊？"）
  - **追溯生产信息**：确认涉及批次的生产日期，和相关影响的产品和客户（例如："这批缺陷还影响哪些产品和客户？"）
  - **正式报告**：包含方法论、注意事项和建议的综合调查（例如："准备一份订阅指标的季度业务回顾"）

- **数据需求**：需要哪些表、指标、维度和时间范围，输入需要处理的方式
 - FILTER_COUNT: 筛选后计数（如"有多少..."）
 - FILTER_LIST: 筛选后列举（如"有哪些..."、"是什么..."）
 - AGGREGATION: 聚合统计（如"总计"、"平均"、"最大"）
 - GROUP_STAT: 分组统计（如"按...分组"、"各...的数量"）
 - RANKING: 排名排序（如"排名"、"Top N"、"最高/最低"）
 - TREND: 趋势分析（如"变化"、"趋势"、"对比"）
 - DISTRIBUTION: 分布分析（如"分布"、"占比"、"比例"）
 - DETAIL: 详情查询（如"详细信息"、具体记录）
 - CORRELATION: 相关性分析（如"关系"、"影响"）
 - COMPARISON: 对比分析（如"对比"、"比较"、"vs"）
 - NOT_SUPPORTED: 当前数据不支持此查询

- **输出格式**：数字、表格、图表、叙述或组合
 - 尽量以表格形式输出相关数据，对实时查询，给出相关数据
 - 给出汇总数据时，同时给出得出数据的原始数据和逻辑



### 2. 收集和理解数据
capabilities: file_read, code_execution
skills: data-profiler

**步骤目标**: 读取数据文件，了解数据结构

**输入**: 上下文中的可用文件路径
**输出**: 数据结构概要（列名、类型、样本值、值分布）

**使用以下方式收集数据**

**优先级 1：如果上下文中已有可用文件（CSV/Excel）：**

1. 查看上下文中的"可用文件"部分，获取文件的**容器路径**
2. **使用 data-profiler 技能**进行数据探查，获取：
   - 数据集概要：行数、列数、列分类（维度/指标/时间/文本）
   - 列级分析：空值率、唯一值、值分布、日期范围
   - 数据样本：前 5 行数据预览
   - 关键词匹配：根据用户问题定位数据（客户名、年份、缺陷类型等）
3. 理解数据结构后继续分析

**重要**：用户的自然语言描述（如"我司原因"）可能与数据中的实际值不同。**通过列级分析的值分布**确认数据中的实际取值，再确定正确的筛选条件。

**优先级 2：如果已连接数据仓库 MCP 服务器：**

1. 探索 schema 以找到相关的表和列
2. 编写 SQL 查询以提取所需数据
3. 执行查询并获取结果
4. 如果查询失败，调试并重试（检查列名、表引用、特定方言的语法）
5. 如果结果看起来异常，在继续之前进行完整性检查

**优先级 3：如果未连接数据仓库：**

1. 请用户以以下方式之一提供数据：
   - 直接粘贴查询结果
   - 上传 CSV 或 Excel 文件
   - 描述 schema 以便为他们编写查询
2. 如果为手动执行编写查询，使用 `sql-queries` 技能获取特定方言的最佳实践
3. 获得数据后，继续分析

**探查结果应用于客诉分析**

- 列分类帮助确定：哪些列可作为筛选维度（客户、产品、责任方），哪些列是统计指标（数量、金额）
- 值分布帮助确定：用户描述与数据实际值的映射关系（如"我司原因" → "内部责任"）
- 日期范围帮助确定：数据覆盖的时间段，是否包含用户查询的年份


### 3. 处理数据
capabilities: code_execution
skills: none

**步骤目标**: 执行数据分析，计算统计结果

**输入**: 步骤 2 中获取的数据结构和内容
**输出**: Python print() 输出的统计数据

**⚠️ 关键要求**：代码必须使用 `print()` 输出所有计算结果，否则结果会丢失！



**输出内容应包含**：
- 总数/计数
- 分组统计（数量和占比）
- 识别出的共性特征（如有）


### 4. 回答客户问题
capabilities: text_only
skills: none

**步骤目标**: 将步骤 3 的计算结果格式化为结构化答案

**输入**: 步骤 3 的 print 输出结果
**输出**: 按以下固定格式输出分析结果

---

**输出格式模板**（必须严格遵循）：

**问题分类**: [分类类型，如：特定供应商分析、趋势分析、根因分析、分布统计等]

**标准答案**:
[用一句话直接回答用户问题，关键数字用 **加粗** 显示]

**数据明细**:

| [维度列] | 数量 | 占比 |
|---------|------|------|
| ... | ... | ... |

---

**格式要求**：

1. 表格必须包含"数量"和"占比"两列
2. 占比保留一位小数（如 46.7%）
3. 标准答案中的数字必须加粗
4. 如果数据不支持某项（如质量因素），可标注"数据未提供"

## 注意事项

- 客诉回复通常有时效要求（24-72小时初步回复），注意提醒用户
- 分析过程中注意区分客户端使用问题和产品本身质量问题
- 涉及安全类客诉应提升为最高优先级处理
- 建议跟踪改善措施的执行效果，通常 30/60/90 天验证

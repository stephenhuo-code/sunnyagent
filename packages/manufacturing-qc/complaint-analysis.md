分析客户投诉，追溯原因并提出系统化的改善措施。

## 用法

```
/complaint-analysis <自然语言问题>
```

## workflow


### 1. 理解问题

**步骤目标**: 解析用户问题，确定分析方向

**输入**: 用户的自然语言问题
**输出**: 问题分类结果（文本）

**注意**: 此步骤只做分析和分类，不要读取数据文件或执行代码。

解析用户的问题并确定：

- **复杂度级别**：
  - **快速回答**：单一指标、简单过滤、事实查询（例如："小米2025年客诉多少？"）
  - **趋势分析**：多维度探索、趋势分析、对比（例如："是什么导致了客诉上升？"）
  - **问题根因分析**：分析导致问题的原因，那个环节导致了相关问题（例如："什么原因导致了镜头模糊？"）
  - **追溯生产信息**：确认涉及批次的生产日期，和相关影响的产品和客户（例如："这批缺陷还影响哪些产品和客户？"）
  - **正式报告**：包含方法论、注意事项和建议的综合调查（例如："准备一份订阅指标的季度业务回顾"）
- **数据需求**：需要哪些表、指标、维度和时间范围，输入需要处理的方式
 - FILTER_COUNT: 筛选后计数（如"有多少..."）
 - FILTER_LIST: 筛选后列举（如"有哪些..."、"是什么..."）
 - AGGREGATION: 聚合统计（如"总计"、"平均"、"最大"）
 - GROUP_STAT: 分组统计（如"按...分组"、"各...的数量"）
 - RANKING: 排名排序（如"排名"、"Top N"、"最高/最低"）
 - TREND: 趋势分析（如"变化"、"趋势"、"对比"）
 - DISTRIBUTION: 分布分析（如"分布"、"占比"、"比例"）
 - DETAIL: 详情查询（如"详细信息"、具体记录）
 - CORRELATION: 相关性分析（如"关系"、"影响"）
 - COMPARISON: 对比分析（如"对比"、"比较"、"vs"）
 - NOT_SUPPORTED: 当前数据不支持此查询
- **输出格式**：数字、表格、图表、叙述或组合



### 2. 收集和理解数据

**步骤目标**: 读取数据文件，了解数据结构

**输入**: 上下文中的可用文件路径
**输出**: 数据结构概要（列名、类型、样本值）

**使用以下方式收集数据**

**优先级 1：如果上下文中已有可用文件（CSV/Excel）：**

1. 查看上下文中的"可用文件"部分，获取文件的**容器路径**
2. **使用 data-profiler 技能的第零阶段方法**进行数据探查
3. 理解数据结构后继续分析

**重要**：用户的自然语言描述（如"我司原因"）可能与数据中的实际值不同。必须先查看唯一值，确定正确的筛选条件，再进行分析。

**优先级 2：如果已连接数据仓库 MCP 服务器：**

1. 探索 schema 以找到相关的表和列
2. 编写 SQL 查询以提取所需数据
3. 执行查询并获取结果
4. 如果查询失败，调试并重试（检查列名、表引用、特定方言的语法）
5. 如果结果看起来异常，在继续之前进行完整性检查

**优先级 3：如果未连接数据仓库：**

1. 请用户以以下方式之一提供数据：
   - 直接粘贴查询结果
   - 上传 CSV 或 Excel 文件
   - 描述 schema 以便为他们编写查询
2. 如果为手动执行编写查询，使用 `sql-queries` 技能获取特定方言的最佳实践
3. 获得数据后，继续分析

**数据探查**

使用 data-profiler skills 进行数据探查，生成数据概要描述作为数据处理的基础


### 3. 处理数据，回答客户问题

**步骤目标**: 执行数据分析，回答用户问题

**输入**: 步骤 2 中获取的数据结构和内容
**输出**: 分析结果和答案

**如果用户要求进行初步分析：
   - 确认不良现象的分类（外观/尺寸/功能/可靠性）
   - 评估严重程度和影响范围
   - 检查是否为已知问题或重复发生

3. 追溯生产信息：
   - 确认涉及批次的生产日期、班组、设备
   - 回溯该批次的质检记录
   - 检查原材料批次和供应商信息
   - 查看该时段的过程检验记录

4. 进行根本原因分析：
   - 使用 5 Why 分析法
   - 使用鱼骨图从人、机、料、法、环、测六个维度分析
   - 对比正常品和不良品的差异
   - 识别变化点（4M 变更：Man/Machine/Material/Method）

### 4. 制定改善措施

**步骤目标**: 基于分析结果制定改善措施

**输入**: 步骤 3 的分析结果
**输出**: 改善措施清单

**仅在用户要求的时候生成**
   - **即时措施：** 库存排查、在制品处理、客户端产品处置
   - **短期纠正：** 针对直接原因的快速修复
   - **长期预防：** 针对根本原因的系统改善
   - **横向展开：** 类似产品/过程的风险排查

### 5. 生成客诉分析报告

**步骤目标**: 生成完整的客诉分析报告

**输入**: 步骤 3-4 的分析结果和改善措施
**输出**: 格式化的客诉分析报告

**仅在用户要求的时候生成**
   - 问题概述
   - 时间线（从发现到处理的全过程）
   - 原因分析详情
   - 改善措施计划（含负责人和完成期限）
   - 效果验证计划
   - 给客户的正式回复建议

### 6. 汇总统计分析

**步骤目标**: 对多条客诉数据进行汇总统计

**输入**: 多条客诉数据
**输出**: 汇总统计报表和图表

**仅在用户提供了多条客诉数据且要求时生成**
   - 客诉类型分布（帕累托分析）
   - 客诉趋势图
   - 高频问题识别
   - 重复客诉追踪

## 注意事项

- 客诉回复通常有时效要求（24-72小时初步回复），注意提醒用户
- 分析过程中注意区分客户端使用问题和产品本身质量问题
- 涉及安全类客诉应提升为最高优先级处理
- 建议跟踪改善措施的执行效果，通常 30/60/90 天验证
